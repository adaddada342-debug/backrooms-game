# No Monster Explanation Policy

## Purpose
Traces must not default to entity explanations.

## Emotional Target
absence preserved

## Source Basis
Derived from the uploaded Backrooms research report and its environmental storytelling library.

## Design Rules
- Do not infer a monster caused a trace unless explicitly requested.
- Prefer human routine, maintenance, architecture, time, or unknown system explanations.
- If danger is implied, keep it ambiguous.

## Implementation Notes
- Validation phrase: “Could this remain scary if no creature exists?” If no, redesign.

## Codex Instructions
- Follow this before adding authored or procedural environmental details.
- Prefer fewer, stronger traces.
- Preserve the project thesis: absence, scale, wrongness, curiosity.

## Common Failure Modes
- Monster explanations.
- Decoration spam.
- Lore dump notes.
- Quest clutter.
- Jumpscare setup disguised as environmental storytelling.
