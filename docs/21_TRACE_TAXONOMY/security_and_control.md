# Trace Category: Security and control

## Purpose
Defines how to use the `Security and control` trace category in liminal spaces.

## Emotional Target
implied story without visible actors

## Source Basis
Source report environmental storytelling category `Security and control`. Sample entries:

- 126. CCTV monitor on but showing static: supervision broken, not absent; who was watching before?
- 127. Security sticker peeled from a doorframe: intentional breach; who removed the warning?
- 128. Key cabinet with one labelled key missing: access narrative; which room matters enough to keep open?
- 129. Turnstile unlocked with cable ties: control surrendered pragmatically; who decided order no longer mattered?
- 130. Panic button cover already snapped: emergency once exceeded protocol; who hit it?

## Design Rules
- Use this category only when it supports the level archetype and psychological stage.
- Pick one or two strong traces rather than many weak ones.
- Every trace must create a question and preserve absence.
- Prefer precise physical placement over abstract symbolism.

## Implementation Notes
- This category contains entries 126-150.
- Attach category metadata to generated props.
- Use category weighting by level archetype.
- Combine with freshness and contradiction metadata.

## Codex Instructions
- Before placing one of these traces, read the specific atomic prompt file.
- Do not place all entries from a category in one area.
- If a trace feels like decoration, remove it.

## Common Failure Modes
- Prop clutter.
- Overtelling the implied story.
- Using traces without physical plausibility.
- Turning evidence into a linear quest.
